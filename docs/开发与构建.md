# 开发、构建与首刷边界

## 支持对象

当前仅针对斐讯 M1 的 `EMW3080B / MK3080B@moc / MX1290` 板级和内核 ABI。外壳上同样标记 EMW3080 的其他芯片版本不能据此刷入本项目。不是 RTL8710 / LibreTiny / ESPHome 工程。

上游 SDK：[MXCHIP/mico-os](https://github.com/MXCHIP/mico-os)，基线提交 `9b09de78164940ff3876d2053f8e7dd42ca2b8ba`。开发使用 MiCoder 1.4、ARM GCC 5.4 和 Windows 工具链；这些依赖不随仓库分发。先确认你的获取和使用权利，再准备到根目录 `mico-os/`。

**本次是应用源码预览发布，并非克隆后开箱构建的完整 SDK 发行版。** 以下本地适配尚未全部以获准再分发的 SDK 补丁交付；只克隆上游不会得到相同的配网和 OTA 行为。检查工具会指出与已构建环境的差异，而不是静默放行。

## SDK 适配清单

| 文件 | 必须具备的适配及原因 |
| --- | --- |
| `MiCO/system/config_server/config_server.c` | 在默认路由前调用应用 `config_server_delegate_http(int, HTTPHeader_t*)`；`kNoErr` 代表已处理，`kNotFoundErr` 才继续默认路由；请求头容量 1024 字节；禁止打印含配置的完整 JSON |
| `MiCO/system/easylink/system_easylink_softap.c` | 使用 `M1_SOFTAP_SSID_PREFIX`；SoftAP IP/网关/DNS 为 `192.168.4.1`，掩码 `/24`；底层 DHCP DNS 仍需独立内核补丁 |
| `MiCO/system/mico_system_init.c` | 配置 HTTP 服务保留在首配及联网模式；现有基线中调用已存在，开发改动主要为说明注释 |
| `MiCO/system/qc_test/qc_test.mk` | `DISABLE_MICO_BLUENRG=1` 时排除依赖缺失的 BlueNRG 质检源；其他质检源不变 |
| `libraries/daemons/ota_server/ota_server.c` / `.h` | 在切换新固件前调用 `ota_server_validate_staged_image()`；失败不切换；URL 缓冲为字符串长度加 1，检查主机名和 URL 上限；将冲突的状态函数命名为 `ota_server_state_get` |
| `libraries/protocols/mqtt/MQTTClient.c` | `MQTTYield` 在整个轮询窗口处理下行，不能只处理一次 `cycle` 就退出；涉及亮度命令和 OTA 订阅 |

不应仅为了通过检查而改哈希。目录中其他 SDK 文件或内核也可能影响行为，七个文件的匹配不是整个工具链的安全认证。

```console
python scripts/check_sdk.py --sdk mico-os
```

该命令只读检查七个已知适配文件的字节 SHA-256；换行变化也会导致不同。遇到差异要人工复核，不能宣称上游 SDK 已完成适配。不分发受专有标记约束的源码或包含大段原文的补丁。

## 编译应用

满足上述依赖和适配后，在仓库根目录用 PowerShell 执行：

```powershell
.\mico-os\MiCoder\cmd\Win32\make.exe -f mico-os\makefiles\Makefile HOST_OS=Win32 m1_moc_firmware@MK3080B@mocOS@mocIP@mocSSL@release
```

产物位于 `build/m1_moc_firmware@MK3080B@mocOS@mocIP@mocSSL@release/binary/`。

| 产物 | 用途与限制 |
| --- | --- |
| `.usr.bin` | 带 8 字节长度/双 CRC 头的用户应用；不是完整首刷镜像 |
| SDK `.ota.bin` | 组合 SDK 内核与用户应用；与已验证内核不同，禁止直接刷 |
| SDK `.all.bin` | 涉及启动、内核等完整区域，禁止直接刷 |
| 工具生成的 `.compat.ota.bin` | 门户兼容内核前缀 + `.usr.bin` + 16 字节 MD5；仅用于已核对兼容性的设备；再分发须先确认内核许可 |

`2026.09.17.24` 开发构建的 `.usr.bin` 曾为 84,880 字节；大小不是识别固件的充分依据，不能用它替代哈希、ABI、分区和读回校验。

## 首次刷写

目前实机覆盖的是受控 SWD 分区操作，并非已验收的公众 TTL 流程。首次操作前应具备：

1. 确认真实芯片与分区映射；备份本机启动区、Application、ATE、Parameter1/Parameter2，保存哈希且确认备份可读。
2. 区分逻辑分区和物理地址：用户应用在逻辑 Application 内相对 `0x75000`，不能把此值直接当成 OpenOCD 物理地址。
3. 只对已核对的内核/应用范围写入，保留原机校准、身份与配置数据；更新不是擦除整片。
4. 写后独立读回，确认 CPU 正常运行，再观察串口、真实 Wi-Fi 广播、HTTP、MQTT 和 HA；内部 AP 标志不能替代无线扫描。
5. 预先保留救援工具和本机镜像；不得使用他人带凭据或校准数据的 Flash 备份。

不确定接线、电压、分区或镜像来源时停止。不同下载器接口可能不是同一编号，不能只按导线颜色连接，也不要把 USB 5V 接到 3.3V 信号脚。

当前不提供可直接复制执行的通用擦写命令，以免把单台开发板的分区方法误当成全型号方案。原版 TTL 全流程验收及合法首刷包准备好后，将单独发布带版本、校验值和救援步骤的安装手册。

## 不接硬件的回归

```console
python scripts/run_tests.py
```

需要 Python 3、Node.js 与 GCC 在 PATH。输出只写 `output/`，不连接串口、SWD、HA 或 MQTT。扫描测试直接抽取应用源码中的生产函数，而不是用另一套模拟算法替代。

公开前先按白名单暂存，再执行 `python scripts/audit_public.py`，人工核对暂存文件与差异。禁止 `git add .` 把整个开发环境当发布包；当前 `.gitignore` 的白名单是一层防护，不是许可证和隐私审查的替代品。
