# 磐石工作室 · 斐讯 M1 本地配网与 Home Assistant 固件

由 **磐石工作室** 维护，项目仓库：`pans-phicomm-m1-homeassistant`。

让闲置的斐讯悟空 M1 继续使用：保留原机 Wi-Fi 模块、屏幕和传感器，用中文网页配置 Wi-Fi / MQTT，通过 Home Assistant 查看空气数据、调节亮度，并提供兼容 OTA 更新链路。

**本项目公开应用层 C 源码、测试和工具，不是仅提供固件下载的仓库。** 面向 `EMW3080B / MK3080B@moc / MX1290` 版本；底层仍依赖 MiCO SDK 和特定兼容内核，并非全栈开源系统，也不是 ESPHome 或 Tasmota 移植。

> **当前为开发者预览版，应用版本 `2026.09.17.24`。**
> 2026-09-18，测试用户已完成手机配网并接入 HA；传感器及亮度控制已有实机验证。首次从原厂固件经 TTL 安装的完整流程、当前版本无线 OTA 全链路及长期稳定性仍需验收。热点曾出现不可见并经复位恢复，尚未定位根因。此仓库不附带第三方完整固件、私有 SDK、个人配置或设备备份。

## 为什么重写

最初目标不是让 M1 多一个固件名字，而是改善旧设备在今天的本地智能家居中的使用过程：Wi-Fi 连接失败难判断、配置依赖额外 App、MQTT 参数不方便修改、更新时担心丢失 Wi-Fi 密码，以及只能看到“不可用”却不知道哪一层出了问题。

本项目把重点放在下面几件事：

| 重点 | 本项目的实现 | 对使用者的意义 |
| --- | --- | --- |
| 手机浏览器配网 | `M1-Setup-xxxxxx` 热点、`192.168.4.1`、中文门户；支持 HTTP 连通性探测引导 | 安装完成后不必再装专用 Android App；未自动弹页也有固定入口 |
| 扫描选择 Wi-Fi | SSID 后方扫描按钮；扫描中提示；同名合并；按信号强度排序；最多 64 个不同 SSID；紧凑单行列表 | 少输名称，避免 Mesh 同名 AP 挤满列表；失败与超时有提示 |
| Wi-Fi 与 MQTT 一起配置 | 网页填写 Wi-Fi 密码、Broker 地址、端口、用户名和密码 | 同一份应用代码不绑定开发者的网络、MQTT 账号或 HA 地址 |
| 日后直接访问设备 | 联网后保留 HTTP 管理页，显示当前 IP、SSID、版本及 MQTT 是否已配置 | 修改 MQTT 不必拆机接串口；“已配置”不等于 Broker 已连接 |
| 原生 MQTT Discovery | 自动发布四项传感器和亮度控制实体 | 已配置 HA MQTT 集成后，无需逐个手写传感器 YAML |
| 面向 HA 的 OTA | MQTT 更新命令、版本/进度/错误字段，配套 MQTT Update Discovery 生成工具 | 管理员配置好更新包后，使用者可从 HA 更新实体发起安装；还不是自动订阅 GitHub Releases |
| 配置与升级包分离 | Wi-Fi/MQTT 留在设备参数区，通用更新包不嵌入用户密码 | 发布者不需要知道每个用户的 Wi-Fi 密码；日常更新不以恢复出厂为前提 |
| 可检查、可扩展 | 传感器协议解析、串口控制、网络恢复、网页和 OTA 应用代码公开，并附主机回归测试 | 可自己维护，而不是只能等待原作者的二进制更新 |
| 可诊断 | MQTT 状态提供 IP、RSSI、串口计数、原始帧、OTA 状态；提供在线/离线与 Last Will | 帮助区分 Wi-Fi、MQTT、传感器和更新链路的问题 |

这些是实现方向和已有能力，不表示已消除全部网络兼容问题，也不承诺任意路由器、手机或 M1 批次都能工作。

## 已安装设备：三步接入 HA

1. **准备 Broker。** HA 先配置 MQTT 集成，记录 Broker 的地址、端口和账号。HA 网页端口通常不是 MQTT 端口；只有 Broker 与 HA 在同一主机上时才填同一个 IP。
2. **手机配网。** 连 `M1-Setup-xxxxxx`，保持连接无互联网的热点，打开 `http://192.168.4.1/`；扫描并选择 2.4 GHz Wi-Fi，填写密码和 MQTT 信息，点击“保存并应用”。看到“已保存”仅代表写入配置成功，不是 Wi-Fi/MQTT 认证成功。
3. **回到家庭网络。** 手机手动切回家庭 Wi-Fi。在路由器 DHCP 列表找设备地址，访问 `http://设备IP/`；HA 的 MQTT 集成应发现四项传感器和一个亮度实体。MQTT 状态也会上报设备 IP。

没有统一默认 MQTT 账号、密码或固定 Broker 地址。网页不回显已保存密码；仅改 MQTT 时，不输入新 Wi-Fi 密码可保留原网络。当前页面不支持隐藏 SSID 的完整手工首配，也没有“先验证新网络成功、失败自动撤回旧配置”的事务式流程。详见[使用指南](docs/使用指南.md)。

## OTA 会不会清除密码？

**日常兼容 OTA 的设计是不覆盖 Wi-Fi / MQTT 参数。** 镜像不包含用户的参数区，也不再用用户 Wi-Fi 密钥给通用更新命令签名。

升级包由兼容内核前缀、新用户应用和完整性校验构成；设备先暂存，再检查前缀、长度、应用双 CRC 和包尾 MD5。参数区与应用升级区域分开，但底层会更新启动元数据，不能说 Flash 的参数相关区域“一个字节都不写”。

重要边界：

- 这不等于任意历史配置格式、任意降级都兼容；变更配置结构时必须有迁移策略。
- 当前亮度不是持久化设置；重启会执行启动亮度命令，不能承诺“所有运行状态不变”。HA 历史数据存于 HA，不在 OTA 镜像中。
- CRC/MD5 用于损坏检测，**不是固件发布者数字签名**；HTTP 与 MQTT 更新路径必须处于可信网络。
- 当前公共分支还不能宣称已经通过断电恢复、自动回滚和完整无线 OTA 配置保留验收。

操作步骤及维护者如何提供 HA 更新按钮见 [OTA 指南](docs/OTA指南.md)。

## 首刷与构建：先看边界

仅凭模块外壳上的 `EMW3080` 字样不足以判定兼容。必须核对本项目支持的芯片/板级定义、内核 ABI 与分区，并保存自己的完整 Flash 备份。**不要把本仓库理解为已经验收的通用 TTL 一键刷机包。**

源码构建依赖单独取得的 MiCO SDK、MiCoder 工具链和本项目列出的 SDK 适配。上游 SDK 不可不加检查直接编译刷机；SDK 自动生成的 `.all.bin` 和 `.ota.bin` 不可直接使用。`0x75000` 是逻辑 Application 分区内的用户应用相对偏移，不是通用物理 Flash 地址。

首次公开只发布源码与文档，不分发第三方内核及整包固件；完整构建条件、所需适配和校验方式见[开发与构建](docs/开发与构建.md)。

## 代码结构

```text
m1_moc_firmware/
  main.c                     启动与服务组合
  m1_sensor_parser.*         主控帧解析，独立于网络
  m1_sensor_uart.*           串口接收、查询和亮度控制
  m1_wifi_scan.*             扫描、去重排序及重连
  m1_setup_portal.c          中文网页、状态与配置接口
  m1_captive_portal.*        配网 DNS 引导
  m1_settings.*              MQTT 持久化及校验
  m1_ha_mqtt.*               MQTT Discovery、控制和诊断
  m1_ota.*                   OTA 参数与暂存镜像校验
  tests/                    主机回归测试
  tools/                    内核补丁、兼容打包和 HA 更新配置工具
docs/                       中文使用、OTA、开发和验收说明
scripts/                    测试与公开发布检查
```

在有 Python 3、Node.js 和 GCC 的环境中运行：

```console
python scripts/run_tests.py
```

主机测试不访问真实设备，也不能替代刷写、无线网络和电源中断试验。
